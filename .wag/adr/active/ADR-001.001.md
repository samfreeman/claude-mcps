# ADR 001.001: Orient on an existing project

**PBI:** [.wag/backlog/epic-001-wagc/PBI-001.md](../../backlog/epic-001-wagc/PBI-001.md) — PBI 001.001
**Epic:** [.wag/backlog/epic-001-wagc/epic.md](../../backlog/epic-001-wagc/epic.md) — Epic 001
**Status:** approved
**Feature branch:** feature/PBI-001.001

## Issue Summary

- **Type:** feature
- **Priority:** high
- **Effort:** M
- **Description:** The first wagc slice. CV connects to the server, calls the one wag tool with a project name, and hears a true answer: the phase, the position in plain words, the next step, and the ritual for running that phase's conversation by voice. Nothing is written. The slice fixes the tool's shape for good (one tool, `wagc`), the name-is-repo resolution rule, the derivation of phase and position from artifacts (Architecture decision 7 as corrected by SNAG-001), the voice-first response, the refusal shape, and the test setup the rest of Epic 001 inherits. It also moves the GitHub module under `lib/modules/` and retires the two raw read tools from the surface.
- **Acceptance criteria:** (from the PBI)
  - From CV on an iPad, connected to the server, asking to orient on this project (claude-mcps) returns its phase, a correct position, and a suggested next step.
  - With an open snag file present in the repo, orient reports tri as the only permitted next step regardless of phase.
  - With an active ADR whose status is approved and no PR on the feature branch, orient reports dev as the next step.
  - With a PR open and no review file for the PBI, orient reports rvw as the next step.
  - Orient on an unknown project name returns a refusal naming the problem.
  - A state file missing a required field, or failing validation, produces a refusal that names the field, never a default.
  - Orient makes no writes to GitHub or Dropbox.
  - The response carries ritual text sufficient for CV to run the next phase's conversation without reading any file from claude-home.

## Technical Context

- **Affected modules:** `app/api/[transport]/route.ts` (the route: secret gate, environment parse, tool registration); `lib/github.ts` (moves to `lib/modules/github/`); new `lib/wag/` (entry, schemas, derivation, rendering, rituals); new `tests/`; new `.github/workflows/ci.yml`; `package.json`, new `vitest.config.ts`, new `next.config.ts`; `README.md`.
- **Current implementation:** One MCP route built with `createMcpHandler`, gated by a shared secret in a header. `lib/github.ts` builds an Octokit at import time from `GITHUB_TOKEN` and registers two tools, `read_file` and `list_tree`, both thin wrappers over the Contents API. No tests, no CI, no Next config file. State file for this repo is wag2's shape.
- **Problem statement:** There is no wag surface. CV can read files but cannot ask where a project is, and nothing on the server knows wag's rules. The v1 tools also expose raw repo access on the one surface CV sees, which the PRD rules out.

## Architecture Decisions

### Decision 1: One tool, named `wagc`, with three optional parameters

**Choice:** The surface registers exactly one tool, `wagc`. Called with nothing it returns the guide. Called with `project` and no `continuation` it orients. Called with a `continuation` it acts, and in this slice every continuation is refused as not yet available. The full input shape is declared now so later PBIs change the engine, never the tool's signature.

**Alternatives considered:** A small family (`wagc`, `wagc_approve`, `wagc_snag`, `wagc_save`); a separate readme or guide tool; a nested discriminated union for the payload.

**Rationale:** PBI 001.001 says the entry point is the only wag tool CV sees, and PBI 002.003 tests that the tool list holds exactly one. CV never browses a tool list; it follows the ritual the last response handed it, which names the next continuation and payload explicitly, so one tool with one good description is the shape the model sees. The guide on an empty call covers discovery: the description is what CV reads when Sam says "use wagc", and the guide is the long form. The same guide text is passed as the MCP server's `instructions` at initialise, which costs nothing; whether the claude.ai connector surfaces instructions to the model is unverified, so the tool path is the one the acceptance criteria rely on. The payload is loosely typed at the transport and strictly parsed by the engine per continuation and phase, which keeps the validation policy intact without bloating the description with a union CV would have to read.

**Code example:**

```typescript
// lib/wag/entry.ts
export const registerWagc = (server: McpServer, deps: Deps) => {
	server.registerTool(
		'wagc',
		{
			title: 'wagc',
			description: 'wag in the cloud. Build a project end to end by voice: discovery, docs, ADR, dev run, review, merge. Call with no arguments to get the guide. Call with a project name to hear where it is and what comes next. Call with a continuation only when the previous response told you to.',
			inputSchema: {
				project: z.string().regex(/^[A-Za-z0-9._-]{1,100}$/).optional()
					.describe('Project name, which is also its repo name, e.g. gigger. Omit for the guide.'),
				continuation: z.enum(['approve', 'snag', 'save']).optional()
					.describe('Omit to orient. approve = phase complete, act and advance. snag = halt on an upstream doc defect. save = record work so far.'),
				payload: z.record(z.unknown()).optional()
					.describe('What the continuation carries. The orient response tells you exactly what to put here.')
			}
		},
		async ({ project, continuation }) => {
			if (continuation != null)
				return render(refusal.notYetAvailable(continuation))
			if (project == null)
				return text(await deps.rituals.read('guide'))
			return render(await orient(project, deps))
		})
}
```

### Decision 2: A project name is its repo name

**Choice:** `project` resolves to `${GITHUB_OWNER}/${project}` with no registry. "Known to the server" is discovered: the repo exists and holds `.wag/` on `dev`. The planet (Dropbox) is consulted only when no repo exists, which arrives with PBI 001.002; in this slice a name with no repo is refused as unknown.

**Alternatives considered:** A registry JSON file in this repo (every registration would trigger a Vercel deploy); a dedicated registry repo (a second store to keep in step with GitHub); an environment-variable map (not writable by init or adoption); a Dropbox file (Dropbox is not a wag state store once a repo exists).

**Rationale:** GitHub is the truth and every disk is a cache. A registry is a second store the server must write during init and adoption and could fail half way through; the repo's existence is the registration. Existing projects' planet folders never enter resolution because the planet only matters before a repo exists, and by then the server created that folder from the same name, so the match holds by construction. This is the same argument that retired the stored phase in SNAG-001. No alias map: Sam confirmed the spoken name and repo name coincide for every existing project.

**Code example:**

```typescript
// lib/wag/orient.ts
const repo = await github.getRepo(project)          // Contents of repos.get, or null on 404
if (repo == null)
	return refusal.unknownProject(project, env.GITHUB_OWNER)
```

### Decision 3: Rituals embedded, authorities fetched

**Choice:** Each phase's ritual is a markdown file in `lib/wag/rituals/`, written for voice, derived from the wag2 command text with everything that assumes a shell removed. Rituals are read from disk at first use and memoised per function instance. Anything the server later *enforces against* (template manifests, the snag template, the ADR section list) is read from claude-home at a pinned ref through the GitHub module and cached by ref and path; this slice needs none of those reads, so that path lands with PBI 001.003 under this decision.

**Alternatives considered:** Fetch the rituals from claude-home at request time (the wag2 command files tell the reader to run git and read files; returned verbatim to CV they would instruct it to do things it cannot); embed the manifests as well (a copy that lags claude-home makes the server pass docs wag2 would fail); import the markdown as modules (needs matching loader rules in webpack and Turbopack, and a different import form under Vitest).

**Rationale:** The ritual is half of the server's own contract: it tells CV which continuation comes next and what the payload must hold, and the engine acts on that payload. One repo, one deploy, one contract. The authorities are the wag process itself and belong to the toolkit pin, like the toolkit in runs. Reading markdown from disk needs one line in `next.config.ts` so Vercel traces the directory into the function bundle, and works identically in tests.

**Ritual files and their required content:**

| File | Must contain |
|---|---|
| `guide.md` | What wagc is; the phases in one line each; how to orient (ask for a project by name); the three continuations and that they are coming; what is not yet available in this release (starting a project by voice is PBI 001.008, adopting one is PBI 001.012, so for now create from CC); the voice rules. |
| `voice.md` | The shared preamble prefixed to every phase ritual (see Decision 5). |
| `adr.md` | The pick (eligible PBIs, the default, blocked as a footnote); the grill (one decision at a time; read summaries, not code; confirm each decision aloud); what approve will do (write the ADR, branch, state, in one commit, from PBI 001.004); the confirmation to obtain before approve. |
| `dev.md` | What approve will do (dispatch a run, PBI 001.005); what orient says while a run is in flight; the merge position (checks, mergeability, review present, from PBI 001.006). |
| `rvw.md` | What approve will do (dispatch a review, PBI 001.007); how to speak a verdict (headline first, then per-axis, then required actions); the dispositions grill on request-changes. |
| `tri.md` | The halt (tri is the only step); the resolution protocol in voice form (fix at source, propagate to docs, propagate to backlog, disposition); what approve will do (PBI 001.009). |
| `docs.md` | The authoring conversation for PRD, Architecture, epics and PBIs; stash triage; what approve checks (PBI 001.003). |

Every ritual states plainly which of its continuations this release supports. In this slice the honest answer is none, and the ritual says "the server does not act on this yet; note the decision and carry it to CC". A ritual that promises a continuation the engine refuses would teach CV to make calls that fail.

**Code example:**

### Decision 4: Phase and position derived from artifacts, REST reads in three parallel stages

**Choice:** Orient derives both phase and position from GitHub on every call and stores nothing. The reads are plain REST through the GitHub module, arranged so that each stage's calls run in parallel:

| Stage | Calls | Purpose |
|---|---|---|
| 0 | `repos.get` | repo exists (else unknown project) |
| 1 | `repos.listBranches` | find `feature/PBI-*` branches, choose the **working ref** |
| 2 | read `.wag/state.json`; `repos.getBranch` then `git.getTree(recursive)`; `pulls.list(head)` | state, the `.wag/` listing, the PR for the branch |
| 3 | ADR header; latest review header; `checks.listForRef(head sha)`; in the pick case every open PBI's header | the artifact facts |

**Working ref.** wag2 commits the ADR, the state that names the feature branch, snags raised during dev, and review files on the feature branch. `dev`'s state file is always in its between-PBIs shape. So orient first lists branches and keeps those named `feature/PBI-*`: none means the working ref is `dev`; exactly one means that branch; more than one refuses (ambiguous branch). Every `.wag/` read then happens at the working ref. When the working ref is a feature branch, `state.feature_branch` must equal its name or the state is refused as invalid.

**Facts gathered** (the `Facts` interface below): open snag files; the active ADR and its status; the working ref and whether it is a feature branch; the PR for the branch (none, open, merged; a closed unmerged PR counts as none) with its check rollup; the latest review for the active PBI (none, APPROVE, REQUEST_CHANGES, and whether a `## Grill dispositions` section exists); stash items; and in the pick case the open PBIs with their priority and dependencies.

**Rules, in precedence order.** The first match fixes the phase; every fact still populates the position.

| # | Condition | Phase | Position |
|---|---|---|---|
| 1 | any file under `snags/` not under `_resolved/` | tri | Open snags listed; the only permitted step |
| 2 | working ref is `dev` and an active ADR exists | dev | Closure pending for the ADR's PBI (a merged PR whose closure did not run, or an ADR committed on dev by hand) |
| 3 | feature branch and no active ADR | refusal | branch without ADR |
| 4 | ADR status draft | adr | Grill in progress on the named PBI |
| 5 | ADR approved, PR none | dev | Ready to dispatch |
| 6 | PR open, no review | rvw | Awaiting review; checks reported |
| 7 | PR open, review REQUEST_CHANGES, no dispositions | rvw | Dispositions pending |
| 8 | PR open, review APPROVE or dispositions present | dev | Merge position; checks and mergeability reported |
| 9 | PR merged, ADR still active | dev | Closure pending |
| 10 | no feature branch, stash items present | tri | Cycle-end tri offered; picking a PBI is also allowed |
| 11 | no feature branch, nothing pending | adr | Between PBIs; eligible count and suggested default |

Rule 10 uses the stash only in this slice; PBI 001.009 adds the latest review's snag candidates when it delivers cycle-end tri. Rule 11 computes eligibility exactly as `/wag:adr` does: a PBI is eligible when every dependency's file lives under `_completed/`, future-bucket PBIs are blocked by their deferral dependency, and the default is chosen by highest priority, then the same epic as `active_epic`, then lowest epic number, then lowest local number. This slice reports the eligible count, the default, and the blocked count; PBI 001.004 owns the full pick ritual.

**Alternatives considered:** One GraphQL snapshot plus one batched body read (two round trips in every case; parked as PBI 501.007); a tarball download (one call, but the whole repo, untarred inside the function); caching derivations (the phase must be true on every call and the reads are cheap).

**Rationale:** About a second per orient on a warm function, inaudible from CV. The reads reuse the module's existing Contents and Trees operations, each is trivially stubbed, and each response has its own small schema. The rule table is the contract PBI 501.007 later reruns unchanged against a faster read path. Keep it simple; optimise when it can be heard.

**Code example:**

```typescript
// lib/wag/derive.ts
export const derive = (facts: Facts): Orient | Refusal => {
	if (facts.snags.length > 0)
		return orient('tri', 'halted', facts, 'tri')
	if (!facts.branch && facts.adr)
		return orient('dev', 'closure-pending', facts, 'merge')
	if (facts.branch && !facts.adr)
		return refusal.branchWithoutAdr(facts.branch.name)
	if (facts.adr?.status == 'draft')
		return orient('adr', 'grill', facts, 'approve')
	if (facts.adr?.status == 'approved' && facts.pr == null)
		return orient('dev', 'ready', facts, 'approve')
	if (facts.pr?.state == 'open' && facts.review == null)
		return orient('rvw', 'awaiting-review', facts, 'approve')
	if (facts.pr?.state == 'open' && facts.review?.verdict == 'REQUEST_CHANGES' && !facts.review.dispositions)
		return orient('rvw', 'dispositions', facts, 'save')
	if (facts.pr?.state == 'open')
		return orient('dev', 'merge', facts, 'approve')
	if (facts.pr?.state == 'merged')
		return orient('dev', 'closure-pending', facts, 'merge')
	if (facts.stash.length > 0)
		return orient('tri', 'cycle-end', facts, 'approve')
	return orient('adr', 'pick', facts, 'save')
}
```

### Decision 5: The response is voice first, four sections, text only

**Choice:** Every orient renders to one text block with four sections in a fixed order: the **opener** (one to three sentences CV says verbatim before anything else), **Position** (the facts as short bullets), **Ritual** (the voice preamble then the phase ritual), and **Next call** (the continuation and payload in words). The opener is built by a template per derivation rule and, where the artifacts allow more than one next step, names both ("You can pick the next PBI for an ADR, or author docs first"). No structured content in this slice.

**Alternatives considered:** Structured content alongside text (nothing programmatic reads orient yet; the render is templated from the record so a structured field can be added later without touching derivation); prose without fixed sections (CV would have to find the opener each time); the ritual first (the listener needs to know where they are before how to proceed).

**Rationale:** Sam listens with eyes closed. Confirmation of where the project is has to be the first thing spoken, in plain words, before any instruction. A fixed shape lets CV learn it once and behave the same in every session.

**The voice preamble** (`voice.md`), prefixed to every phase ritual:

- Say the opener first and wait for acknowledgement before anything else.
- One question at a time. Never a list of questions.
- Summarise documents; read a file path, identifier or code block aloud only when asked.
- Before any approve, restate exactly what will happen and get an explicit yes.
- After any continuation, confirm what happened in one sentence, then re-orient.

**Code example** (rendered output for rule 5):

```markdown
# gigger — dev

**Say this first:** gigger is in dev. The ADR for PBI 001.003, docs phase with checked
approve, is approved and no run has been dispatched. The next step is approve, which
starts the dev run. This release does not dispatch runs yet, so that step happens from CC.

## Position
- Phase: dev, ready to dispatch
- PBI: 001.003 — Docs phase with checked approve
- Feature branch: feature/PBI-001.003, no PR yet
- Snags: none
- Stash: none

## Ritual
[voice.md, then dev.md]

## Next call
wagc with project "gigger", continuation "approve", and no payload — not available in this release.
```

### Decision 6: One surface; the raw read tools are unregistered; the GitHub module moves

**Choice:** `read_file` and `list_tree` are removed from the surface. Their code becomes the GitHub module's first operations under `lib/modules/github/`, and `lib/github.ts` is deleted. The module is a factory that takes an Octokit instance and returns operations, so tests pass a stub and the route passes the real client. Nothing in the module knows about phases.

**Alternatives considered:** Keep the two tools registered (violates the PBI and PBI 002.003); a second route with the raw tools now (Sam decided base-level tools go in a future MCP; PBI 501.004); a module-level Octokit singleton (untestable without environment).

**Rationale:** MCP has no hidden tools; a registered tool is an advertised tool. Architecture's "raw tools stay reachable but unadvertised" is read as: the module operations stay reachable to the server and can be mounted on a separate surface later. Architecture also names this ADR as the one that moves the module.

**Code example:**

### Decision 7: Schemas at every trust boundary

**Choice:** Four boundaries, each a zod schema with `safeParse`; a failure is a refusal naming the field, never a default.

- **Environment**, parsed once per instance, memoised, and only after the secret check passed, so a misconfigured deploy never explains itself to an unauthenticated caller. On failure the route returns a plain-text 500 naming the variable.
- **State file**, wag2's shape exactly, strict on unknown keys. `current_mode` is tolerated and ignored (every wag2 project carries the fossil). A legacy shape missing `active_epic` or `wag_version` refuses with a pointer to run `/wag:update` from CC.
- **Artifact headers**, one anchored regex per line, a schema over the capture: ADR `**Status:**` (draft, approved); review `**Verdict:**` (APPROVE, REQUEST_CHANGES) and the presence of a `## Grill dispositions` heading; PBI `**Priority:**` (P1, P2, P3) and `**Dependencies:**` (None, or `PBI EEE.PPP` references).
- **GitHub responses**, one small schema per operation, picking only the fields used. Octokit's types are compile-time only; the schema is what runs.

**Alternatives considered:** Parse the environment at module load (a throw there gives Vercel a function crash and CV a generic error); passthrough on unknown state keys (signed is not shape-valid); trust Octokit's types (compile-time only).

**Rationale:** Architecture's validation policy states the boundary as every value from outside the process given a typed identity. The `GITHUB_OWNER` default is the one deliberate default: a declared schema value for an absent optional, not a value substituted for one that failed to parse, matching what the old tools did.

**Code example:**

```typescript
// lib/wag/state.ts

	current_mode: z.string().nullable().optional(),
	active_epic: z.string().regex(/^epic-\d{3}-[a-z0-9-]+$/),

// lib/wag/artifacts.ts
```

### Decision 8: Refusal is a value in the orient shape; error is `isError`

**Choice:** A refusal is a normal tool result rendered in the four-section shape: the opener carries the refusal sentence, then **Why**, then **What to do**. In code it is a value (kind, sentence, reasons, next steps) returned up the stack, never thrown. An unexpected failure (GitHub 5xx, timeout, bug) is a result flagged `isError` with one plain sentence naming the operation and suggesting a retry; the full error goes to the function log. A wrong or missing secret stays an HTTP 401 before the MCP layer.

**Refusal kinds in this slice:**

| Kind | Trigger | What to do says |
|---|---|---|
| unknown project | no repo for the name | check the name; create from CC until PBI 001.008 |
| not a wag project | repo exists, no `.wag/` at dev | run wag init from CC; adoption arrives with PBI 001.012 |
| invalid state | schema failure, naming the field | fix the field; legacy shapes point to `/wag:update` |
| ambiguous branch | more than one `feature/PBI-*` branch | close or delete one from CC |
| branch without ADR | feature branch, no active ADR | approve an ADR on it from CC, or delete it |
| unreadable artifact | header line missing or invalid, naming the file | fix the file from CC |
| listing truncated | GitHub truncated the tree | the repo's `.wag/` is too large; report |
| not yet available | a continuation this release does not implement | carry the decision to CC |

**Alternatives considered:** `isError` on refusals (clients render it as "the tool broke" and the model apologises and stops); throwing exceptions for refusals (loses the structured what-to-do).

**Rationale:** The split matches the outcome triad PBI 002.001 will log: acted, refused, failed. Eyes closed, a refusal reads as "I can't orient on gigger, no repo exists" followed by the fix, not "there was an error with the tool".

**Code example:**


### Decision 9: Vitest, offline unit tests, self-skipping live tests, CI on the PR

**Choice:** Vitest with tests under `tests/`. Unit tests are offline: table-driven derivation over every rule and refusal kind; state and environment validation; artifact headers; render of every opener; the GitHub module against a stubbed Octokit with one malformed response per operation. Live tests use the MCP SDK client over streamable HTTP against the deployed endpoint and skip themselves when `WAGC_ENDPOINT` and `WAGC_SECRET` are absent. A GitHub Actions workflow runs typecheck and tests on every PR to `dev` and every push to `dev`.

**Alternatives considered:** Jest (needs a transform for TypeScript and ESM); mocking libraries (the module factory makes a stub a plain object); branch protection to block a red PR (Pro-only on private repos; the wagc merge gate in PBI 001.006 and `/wag:dev`'s Phase 6 read the check rollup instead).

**Rationale:** `/wag:dev`'s CQ role runs lint, build and test per task and the full gate before commit, and Phase 6 reads the PR's check rollup before merge. The project needs named scripts for that, a `tests/` directory the Tester owns, and a check on the PR for the rollup to carry. The derivation suite is the contract PBI 501.007 later reruns against a different read path.

**Code example:**

```typescript

// lib/wag/types.ts
export type Phase = 'discovery' | 'init' | 'docs' | 'adr' | 'dev' | 'rvw' | 'tri'

export type Position =
	| 'halted' | 'grill' | 'ready' | 'awaiting-review' | 'dispositions'
	| 'merge' | 'closure-pending' | 'cycle-end' | 'pick'
export type RitualName = 'guide' | 'voice' | 'adr' | 'dev' | 'rvw' | 'tri' | 'docs'

export type PbiId = { epic: string, pbi: string }          // '001', '003' → PBI 001.003

export type Facts = {
	project: string
	workingRef: string                                       // 'dev' or the feature branch
	branch: { name: string, head: string } | null
	state: State
	snags: string[]                                          // paths under .wag/snags/, excluding _resolved/
	adr: { path: string, status: 'draft' | 'approved', pbi: PbiId } | null
	pr: { number: number, url: string, title: string, state: 'open' | 'merged', checks: CheckRollup } | null
	review: { path: string, verdict: 'APPROVE' | 'REQUEST_CHANGES', dispositions: boolean } | null
	stash: string[]
	pick: { eligible: PbiSummary[], blocked: number, suggested: PbiSummary | null } | null
}
export type CheckRollup = 'none' | 'pending' | 'green' | 'red'
export type PbiSummary = { id: PbiId, title: string, priority: 'P1' | 'P2' | 'P3', dependencies: PbiId[] }

export type Orient = {

	phase: Phase

	next: Continuation | 'merge' | 'tri' | 'pick'

export type RefusalKind =
	| 'unknown-project' | 'not-a-wag-project' | 'invalid-state' | 'ambiguous-branch'
	| 'branch-without-adr' | 'unreadable-artifact' | 'listing-truncated' | 'not-yet-available'

export type Deps = { github: Github, rituals: { read: (name: RitualName) => Promise<string> } }
```

## Testing Strategy

- **Unit tests:**
  - Derivation: one row per rule in Decision 4 (eleven rules) plus every refusal kind that derivation can return, each a fixture of facts, asserting phase, position and next.
  - State: valid; each required field missing (naming it); legacy shape (naming `/wag:update`); unknown key; malformed JSON. Environment: valid; each variable missing; owner default applied.
  - Artifact headers: ADR status valid, missing, foreign; review verdict valid, missing, foreign, with and without a dispositions heading; PBI priority and dependencies including `None` and cross-epic references.
  - Eligibility and default: fixtures with a closed dependency, an open dependency, a future-bucket PBI, ties broken by priority then epic then number.
  - Render: the opener for every rule and refusal, asserted as text; the full four-section output once for an orient and once for a refusal.
  - GitHub module: each operation against a stub Octokit returning recorded JSON; a 404 path where the operation returns null; one malformed response per operation refused by its schema.
- **Integration tests:** `tests/live/`: the tool list contains exactly `wagc`; orient on `claude-mcps` returns a phase, a position and a next step; a request without the secret is rejected with 401 before any tool runs. Skipped when the endpoint variables are absent, so CI never needs network. Acceptance criterion one (from CV on an iPad) is verified by Sam after deploy; the live test is its automated proxy.
- **Edge cases:** two feature branches; a feature branch whose state says `feature_branch: null`; a feature branch with no ADR; two active ADR files; a closed unmerged PR; a PR merged with the branch still present; a truncated tree; a state file with the `current_mode` fossil; a repo with no `.wag/`; a tree with `snags/_resolved/` entries only; a review file for a different PBI than the active one; a PBI whose dependency file is under `_completed/` of a different epic.

## What NOT to do

- **Do not store a phase, a position, or any derived fact.** State keeps wag2's exact shape. SNAG-001 retired the stored phase; do not bring it back under another name (a cache file, a hidden field, a registry).
- **Do not register a second tool.** No readme tool, no raw file tools, no per-phase tools. PBI 002.003 tests for exactly one.
- **Do not read `.wag/` only from `dev`.** The ADR, the feature-branch state, dev-time snags and reviews live on the feature branch. Find the working ref first.
- **Do not default on a validation failure.** A missing field, an unknown key, a foreign header value, a truncated tree: refuse and name it.
- **Do not flag refusals as `isError`.** Refused and failed are different outcomes and CV must hear them differently.
- **Do not import the ritual markdown as modules.** Read from disk with the tracing include. No loader rules.
- **Do not fetch rituals from claude-home.** The wag2 command text is for a harness with a shell. Rituals are authored for voice and live in this repo.
- **Do not build an Octokit at module load or read the environment before the secret check.** Environment is parsed after auth, memoised, and injected.
- **Do not let a ritual promise a continuation this release refuses.** Every ritual says what the server acts on today.
- **Do not add a linter, a GraphQL client, a Dropbox module, or run dispatch.** Those are PBIs 000.x, 501.007, 001.002 and 001.005.
- **Do not write to GitHub or Dropbox anywhere in this slice.** Orient is read-only; the acceptance criteria say so.
