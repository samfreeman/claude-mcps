## Design and code quality
**Axis verdict:** concerns

- Coupling and abstractions are good. `derive` is pure and table-shaped; `render`'s per-position accessors (`lib/wag/render.ts:10-32`) turn a derivation bug into a loud, named throw rather than a quietly wrong spoken sentence, and each guard is tested (`tests/render.test.ts:237-262`). I traced every position's precondition through the rule chain: all four guards are unreachable in practice, which is the right place for them.
- Refusal/error split is clean and matches the outcome triad: refusals are values with `say`/`why`/`next` and never `isError`; failures carry one sentence plus `console.error` to the function log.
- Style: fully compliant with `typescript-rules.md`. No `===`/`!==`, no semicolons, no double quotes outside a template literal, tabs throughout, no trailing commas, no comments, and not one line over 80 columns across `lib/`, `app/` and `tests/`.
- **Test gap on an acceptance criterion.** AC2 is the only criterion whose fact-extraction path is untested: `tests/facts.test.ts:263-273` covers only `_resolved/`-only, and no test drives an open `.wag/snags/SNAG-001.md` (or a `.wag/stash/STASH-001.md`) through `gatherFacts` into `Facts.snags`/`Facts.stash`. If `snagPattern` (`lib/wag/facts.ts:13`) were wrong, the whole suite would still be green and the halt would silently never fire in production.
- `operationOf` (`lib/wag/entry.ts:27-34`) derives the user-facing operation name by splitting an `Error.message` on `:` — an invisible coupling to `shapeError`'s format. Any future `throw new Error('Boom: …')` surfaces "failed while Boom" to the caller. A typed error carrying `operation` would be sturdier.
- Refusal mis-cause: `gatherFacts` maps `getBranchHead(...) == null` (the ref does not exist) onto `not-a-wag-project / no-wag-dir` (`lib/wag/facts.ts:151-152`), so a repo whose default branch is `main` is told "there's no .wag/ directory on dev" when the truth is "there is no dev". The remedy offered is still right, but the reason is not, and this is exactly the case adoption (PBI 001.012) will meet.
- `parseState` flags any issue on `active_epic`/`wag_version` as a legacy shape (`lib/wag/state.ts:48,61-63`), so a *present but malformed* `active_epic` tells Sam to run `/wag:update` rather than to fix the field.
- Efficiency nit: stage 3 computes `pick` unconditionally when there is no feature branch (`lib/wag/facts.ts:171-178`), reading every open PBI — 22 Contents calls in this repo — even when rule 1 will halt on an open snag and discard it.
- Coverage is proportionate to risk: derivation, refusals, artifact headers, eligibility/default ordering, every opener, and each GitHub operation with a 404 path and a malformed response. The lowest-covered file is `facts.ts`, which is where the gap above sits.

## Security
**Axis verdict:** pass

- The gate is genuinely first. `app/api/[transport]/route.ts:32-37` compares the secret before anything else; only then is the environment parsed (`:39`), and only then is an Octokit built (`:15`). Nothing at module scope reads `process.env` or constructs a client, so a misconfigured deploy cannot explain itself to an unauthenticated caller. The env-failure 500 names the variable to an authenticated caller only, as the ADR intended.
- No writes exist anywhere in the process: the `OctokitLike` surface (`lib/modules/github/client.ts:1-45`) admits only read methods, which makes AC7 a structural property rather than a promise.
- Injection via `project`: the tool schema restricts it to `^[A-Za-z0-9._-]{1,100}$` (`lib/wag/entry.ts:43`), so no `/`, no ref or path separators; every path and ref passed to the API is server-constructed from the tree listing or from GitHub's own branch names. `.` and `..` do pass the regex, but the owner is fixed, all operations are reads and GitHub 404s them into an `unknown-project` refusal; anchoring the first character to alphanumeric would close it cheaply.
- Error bodies leak little: refusals carry only the project name, paths, branch names and field names; failures carry a bounded `[A-Za-z]+` prefix from an error message. Logged Octokit errors do not carry the token — `@octokit/request-error` redacts the Authorization header before the object is constructed.
- Accepted-by-design exposures worth stating: a caller holding the shared secret can probe existence of any repo under `GITHUB_OWNER` and read any project's `.wag/`; and free text from the repo (PBI titles, `render.ts:127-129`) is echoed into the model-facing response. Both are same-owner, single-user surfaces, and the slice is strictly narrower than the v1 raw `read_file`/`list_tree` it removes.
- Pre-existing and unchanged on this branch: the secret comparison is not constant-time (`route.ts:36`). Epic 002 owns hardening; noting it so it is not lost.

## Snag candidates
- **`Architecture.md` → `Ubiquitous language` (lines 7-42).** The section is the naming authority but is missing terms the contract and code now depend on: **refusal** (a first-class response shape with eight enumerated kinds), **facts**, **working ref**, and **check rollup**. `guide` and `opener` were added at ADR approval; these were not. Matters because the section is what RVW, DEV and CQ check names against — a term used everywhere in code and absent from the glossary is how synonym drift starts.
- **`Architecture.md` → Data model, line 160** ("derived on each orient from: **the registry** (no repo means discovery)") and **`PBI-001.md` → Deliverables, line 18** ("A project name resolves to a project repo through **a mapping the server owns**"). ADR Decision 2 retired the registry — the repo's existence is the registration — and the approval commit fixed that wording in PBI-008 and PBI-012 but not in these two places (PBI-012's Description line 8 also still says "a registration with the server"). Matters because Architecture is the doc a later ADR reads for the resolution rule, and it currently names a store that does not exist.
- **`Architecture.md` → decision 7 ("Docs is a ritual run from that position") vs `ADR-001.001` → Decision 4's rule table.** No derivation rule yields the `docs` phase, and `DerivedPhase` excludes it (`lib/wag/derive.ts:4,18`), so `lib/wag/rituals/docs.md` — required by Decision 3 and shipped in full — can never be returned. Rule 11's opener actively offers it ("or author docs first", `render.ts:80`) with no ritual behind the offer. Matters because it ships dead weight and leaves a spoken option unsupported.
- **`ADR-001.001` → Decision 7 (line 267) vs Decision 8 (lines 308-324).** Decision 7 says every one of the four boundaries, GitHub responses included, refuses on failure "naming the field"; Decision 8's refusal-kind table has no kind for an unexpected response shape and reserves `isError` for exactly that class. The implementation follows Decision 8 and Architecture's validation policy. Matters because PBI 501.007 reruns this contract against a different read path and needs one unambiguous rule.
