# PBI 001.001: Orient on an existing project

**Priority:** P1
**Dependencies:** None

## Description

The first thing Sam does from CV is ask where a project is. This slice delivers the entry point in its orienting form for a project that already has a repo with `.wag/` in it: the server reads the stored phase and the artifacts, derives position, reports where the project is and what comes next, and returns the ritual for that phase. Nothing is written. This is the thinnest end-to-end slice: CV connects, calls the entry point with a project name, and hears a true answer. It also decides the tool count question (Architecture open question 1) in its ADR, since the entry point's shape is fixed here.

Traces to PRD user story "I say wag, gigger and hear where the project is", Architecture decisions 6 and 7.

## Deliverables

- The entry point exists on the server and is the only wag tool CV sees. Called with a project name and no continuation, it orients.
- Orient reads the project's state from the project repo and derives position from artifacts: open snags, the active ADR and its status, the feature branch and its PR, the PR's checks and reviews.
- Orient returns, in one response: the phase, the position in plain words, the suggested next step, and the ritual CV should follow for the phase, including which continuation comes next and what its payload must contain.
- A project name resolves to a project repo through a mapping the server owns; an unknown project is a clear refusal, not an error trace.
- The state file gains the phase field; a project without one is reported as needing a stamp, not silently defaulted.
- The state file and every artifact read are validated at the boundary per the Architecture validation policy.

## Acceptance Criteria

- [ ] From CV on an iPad, connected to the server, asking to orient on this project (claude-mcps) returns its phase, a correct position, and a suggested next step.
- [ ] With an open snag file present in the repo, orient reports tri as the only permitted next step regardless of phase.
- [ ] With an active ADR whose status is approved and no PR on the feature branch, orient reports dev as the next step.
- [ ] With a PR open and no review file for the PBI, orient reports rvw as the next step.
- [ ] Orient on an unknown project name returns a refusal naming the problem.
- [ ] A state file missing the phase field, or failing validation, produces a refusal that names the field, never a default.
- [ ] Orient makes no writes to GitHub or Dropbox.
- [ ] The response carries ritual text sufficient for CV to run the next phase's conversation without reading any file from claude-home.

## Testing Requirements

- [ ] Unit tests for position derivation across the phase and artifact combinations above, with GitHub responses stubbed.
- [ ] Unit tests for state validation: valid, missing phase, malformed.
- [ ] Integration test against the live endpoint with the shared secret, orienting on this repo.
- [ ] Negative test: a request without the shared secret is rejected before any tool runs.

## Technical Notes

The v1 read tools already read files and list trees through the GitHub module; orient builds on those reads. The ritual text for each phase can be derived from the wag2 command files in claude-home, but it is served by the server, not fetched by CV. The ADR decides whether the ritual is embedded in the server or read from the pinned claude-home ref at request time.
