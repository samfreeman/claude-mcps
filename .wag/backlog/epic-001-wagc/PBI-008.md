# PBI 001.008: Init from planet to template repo

**Priority:** P1
**Dependencies:** PBI 001.003

## Description

A project from nothing, by voice. Orient on a project name with no repo reports discovery as the phase and returns the intake ritual. Discovery drafts and decision captures accumulate in the planet through save across as many sessions as needed. Approve in the init position checks the drafts against the manifests, creates the project repo from the template repo, writes the PRD, RESEARCH, Architecture and backlog into `.wag/`, writes state, and commits; the next orient offers the first pick. The template repo is a deliverable here: it carries the workflow from PBI 001.005, the `.wag/` skeleton and the toolkit pin, so the first commit already has everything a run needs. Scaffolding an app baseline inside the new repo is deferred to the future bucket; v1 init produces the planning layer and the workflow, and the first PBI's dev run stands up the app.

Traces to PRD Goals 1 and 2, Architecture decision 9.

## Deliverables

- Orient on an unknown project name offers to begin discovery; on yes, the planet folder is created and the phase is discovery. A project is known to the server from then on.
- The discovery ritual: the intake methodology from wag2, capturing vocabulary as it surfaces, what to draft, and when to save.
- Approve in the init position checks: PRD and Architecture drafts in the planet answer every manifest item, a RESEARCH draft exists, at least one epic with at least one PBI conforms to shape, no repo already exists for the name.
- A passing approve generates a private repo from the template repo (GitHub Free tier; template generation is available on it), writes the drafts into `.wag/docs/` and `.wag/backlog/`, writes state with the wag version, creates the general and future buckets and completed mirrors, commits on dev, and registers the repo against the project name.
- The template repo exists and holds: the workflow file, the `.wag/` skeleton with special buckets, and the pinned claude-home ref the workflow checks out.
- After init, the planet keeps discovery notes and decision captures; the wag docs live only in the repo.

## Acceptance Criteria

- [ ] From CV, naming a new project and beginning discovery results in a planet folder for it and a discovery phase on the next orient.
- [ ] Saving a PRD draft and two decision captures across two separate sessions results in one PRD draft and one dated decision doc per day in the planet.
- [ ] Approving init with complete drafts results in a new private repo generated from the template, with `.wag/` populated, state carrying the wag version, and one initial wag commit on dev.
- [ ] Orient on the project immediately after init reports the adr phase with eligible PBIs.
- [ ] Approving init with a PRD draft missing a manifest item refuses and names it; no repo is created.
- [ ] Approving init for a name that already has a repo refuses.
- [ ] The generated repo contains the workflow file and can dispatch a run without further setup beyond the subscription token secret.

## Testing Requirements

- [ ] Unit tests for the init checks against planet fixtures.
- [ ] Unit tests for the planet-to-repo mapping of drafts into `.wag/` paths.
- [ ] Integration test: full init against a throwaway project name, verifying the repo, the tree and state, then deleting the repo.
- [ ] Negative tests: existing repo, incomplete drafts, Dropbox unreachable.

## Technical Notes

The subscription token secret is per-repo or organisation-level; the ADR decides whether init sets it from a server-held copy or the ritual tells Sam to add it once. Project-name-to-repo mapping is server-owned state (from PBI 001.001) and gains entries here.
