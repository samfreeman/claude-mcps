# PBI 001.003: Docs phase with checked approve

**Priority:** P1
**Dependencies:** PBI 001.002

## Description

The docs phase from CV: orient returns the docs ritual, edits accumulate through save, and approve double-checks the docs before advancing. This is the first approve and the first artifact double-check, so it establishes the pattern every later phase reuses: the server refuses with a reason when artifacts fall short, and acts only when they pass. For docs, the checks are the template manifests for PRD and Architecture, strict record shape for epics and PBIs, versioning and changelog on narrative docs, and the halt on open snags.

Traces to PRD Goal 2, Architecture decision 6 and open question 2.

## Deliverables

- Orient in the docs phase returns the docs ritual: pre-flight findings (open snags, an active ADR to be aware of, pending fixes, stash items), and how to run the authoring conversation.
- Approve in the docs phase checks: every PRD and Architecture manifest item answered; every epic and PBI conforms to its template's shape; narrative docs that changed carry a bumped version and a changelog line; no open snags. A failed check refuses with the specific gap.
- A passing approve commits any unsaved artifacts, and orient then offers the next step (pick a PBI for adr).
- Stash items are surfaced in the ritual and can be triaged through save (promote, defer, fold, discard) using the existing stash conventions.

## Acceptance Criteria

- [ ] From CV, in the docs phase, adding a new PBI to an epic by conversation and approving results in the PBI committed in the right epic folder with the next local number, and orient offering adr next.
- [ ] Approving with a PRD missing a manifest item (for example, no open questions section answered) refuses and names the item; nothing advances.
- [ ] Approving with a PBI file missing a required section refuses and names the file and section.
- [ ] Approving after a PRD edit whose version was not bumped refuses and says so.
- [ ] Approving with an open snag refuses and directs to tri.
- [ ] A stash item promoted to a PBI through save lands as a PBI file and the stash item moves to processed with a footer.

## Testing Requirements

- [ ] Unit tests for each check with fixture docs: passing, each failure mode.
- [ ] Unit tests for next-number computation including the completed mirror.
- [ ] Integration test on a test repo: full docs cycle from orient to approve.
- [ ] Negative test: approve on a project in a different phase refuses.

## Technical Notes

The manifests live as comment blocks at the top of the wag2 templates in claude-home. The server must treat them as the authority and read them from the pinned ref or embed them; the ADR decides, consistent with PBI 001.001's ritual decision.
