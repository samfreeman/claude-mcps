# PBI 001.007: Review run and dispositions

**Priority:** P1
**Dependencies:** PBI 001.006

## Description

The rvw step from CV. Approve in the rvw position dispatches a review run: Claude Code in Actions, cold and independent, reads the ADR, the diff and Architecture, and returns the structured verdict. The server captures it as the next numbered review file on the feature branch, posts it as a PR comment, and orient reports the verdict and headline findings summarised for voice. On request-changes, the ritual runs the grill over the findings and save records the dispositions appended to the review file. Merge then requires a review to exist; an approving verdict is the normal gate and an override is recorded.

Traces to PRD user story "I approve rvw and later hear the verdict", the wag2 rvw command, Architecture decision 6.

## Deliverables

- Approve in the rvw position checks: an open PR on the feature branch, no open snags, no review run in flight. Then dispatches the review run and records it.
- The review run produces the verdict in the wag2 review format, written to the next numbered review file for the PBI on the feature branch and posted as a PR comment tagged as the independent senior review.
- Orient after the run reports the verdict, the per-axis verdicts, and the required actions, in a spoken-summary form, with the written file as the record.
- On request-changes, the ritual grills each required action to fix, reject or snag; save appends the dispositions to the review file and posts them as a follow-up PR comment.
- The merge check from PBI 001.006 gains: a review file exists for the PBI, and its verdict is approve, or an override is present and recorded.
- Snag candidates in the review are surfaced; each is either captured now (through the snag continuation) or left for tri.

## Acceptance Criteria

- [ ] From CV, approving rvw on a project with an open PR starts a review run and, on completion, orient reports the verdict and the headline findings.
- [ ] The review file exists on the feature branch with the next number, and the same content is a comment on the PR.
- [ ] A second review on the same PBI gets the next number and never overwrites the first.
- [ ] With a request-changes verdict, saving dispositions for every required action results in a dispositions section appended to the review file and a follow-up PR comment.
- [ ] Approving merge with no review file refuses and directs to rvw.
- [ ] Approving merge with a request-changes verdict and no override refuses; with an override, proceeds and records it.

## Testing Requirements

- [ ] Unit tests for review numbering and the extended merge check.
- [ ] Unit tests for parsing the review format into verdict, axes and required actions.
- [ ] An end-to-end review run on this repo's own PR from PBI 001.005.
- [ ] Negative test: review run dispatched with no PR refuses.

## Technical Notes

The review uses a comment, never approve or request-changes on the PR, because GitHub blocks self-review on self-authored PRs. The verdict lives in the report header.
