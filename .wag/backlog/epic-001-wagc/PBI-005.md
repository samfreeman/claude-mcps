# PBI 001.005: Dev run to an open PR

**Priority:** P1
**Dependencies:** PBI 001.004

## Description

The first run. Approve in the dev phase dispatches a GitHub Actions job that runs Claude Code on the subscription token with the wag toolkit checked out from claude-home at a pinned ref, implements the approved ADR on the feature branch, and ends at an open PR. Orient while the run is in flight reports its status; orient after it reports the PR. This slice uses a GitHub-hosted runner only; self-hosted runners are PBI 001.011. Asks during the run are PBI 001.010; in this slice a run that cannot proceed simply fails and orient says so.

Traces to PRD Goal 4, Architecture decisions 2, 3 and 5.

## Deliverables

- A workflow file in the project repo (this repo first, the template later) that on dispatch checks out the project and claude-home at a pinned ref, builds the toolkit's MCP servers, and runs Claude Code with the wag dev instructions for the active ADR, authenticated by the subscription token stored as a repository secret. GitHub Free tier; workflow dispatch and repository secrets are available on it.
- Approve in the dev phase checks: an approved ADR exists, the feature branch exists, no open snags, no run already in flight for this branch. Then dispatches the run and records its identity so orient can find it.
- Orient during a run reports it as in flight with elapsed time; after it, reports the PR URL and title, or the failure reason.
- The run ends at an open PR from the feature branch to dev with a body derived from the ADR. It never merges, never moves the ADR or PBI, never touches state.
- The Actions job uses the subscription token only; no Anthropic API key exists in any secret.

## Acceptance Criteria

- [ ] From CV, approving dev on a project with an approved ADR results in a workflow run starting within a minute, visible in the repo's Actions tab.
- [ ] Orient during the run reports it in flight; orient after completion reports the open PR's URL.
- [ ] The PR is from the feature branch to dev, and the ADR, PBI and state files are unchanged by the run.
- [ ] Approving dev while a run is already in flight for the branch refuses and reports the existing run.
- [ ] The run's log shows Claude Code authenticated by the subscription token, and the repo has no API key secret.
- [ ] A run that fails leaves the branch as it was and orient reports the failure with a pointer to the log.

## Testing Requirements

- [ ] Unit tests for the dev approve checks and for run-state derivation from the Actions API.
- [ ] An end-to-end run on this repo against a trivial ADR, verified by the resulting PR.
- [ ] Negative test: dispatch with a missing secret fails fast with a clear message in the log.

## Technical Notes

Verified against docs on 2026-09-04: the official action accepts a subscription OAuth token and runs in automation mode on any event with a prompt input. Whether the Agent tool and team shape run inside the runner is unverified; the ADR should plan for a single confined agent as the fallback. Set a workflow timeout and a turn cap so a runaway run cannot consume the subscription.
