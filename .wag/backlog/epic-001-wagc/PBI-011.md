# PBI 001.011: Self-hosted runners with hosted fallback

**Priority:** P2
**Dependencies:** PBI 001.005

## Description

Make runs free and warm when a laptop is on, and still possible when none is. Each of Sam's laptops registers as a self-hosted GitHub Actions runner inside WSL, with the toolkit checkout warm, and the workflow prefers a self-hosted runner and falls back to GitHub-hosted when none is online. Orient reports which runner a run landed on. Repos stay private because self-hosted runners must never serve a public repo.

Traces to PRD constraint "works with the laptops off", Architecture decision 4.

## Deliverables

- A documented, repeatable registration of a laptop's WSL as a self-hosted runner for Sam's repos, started as a service so it polls whenever WSL is up. GitHub Free tier; self-hosted runners are available on it.
- The workflow targets self-hosted runners when one is online and GitHub-hosted otherwise, without a manual choice per run.
- A self-hosted run reuses a warm claude-home checkout at the pinned ref and built MCP servers, and skips bootstrap when the pin is unchanged.
- Orient reports the runner a run is on, and the ritual mentions fallback minutes when a run lands on GitHub-hosted.
- The generated project repos from the template are private, and the template's workflow carries the runner preference.

## Acceptance Criteria

- [ ] With one laptop's runner online, approving dev results in the run executing on that runner, visible in the run's metadata, and orient reporting it.
- [ ] With no runner online, the same approve results in the run executing on a GitHub-hosted runner, and orient noting the fallback.
- [ ] A self-hosted run with an unchanged pin skips the toolkit clone and build and starts work within a minute of pickup.
- [ ] Registering a second laptop by following the documented steps takes under fifteen minutes and needs no change to any repo.
- [ ] Every repo with a self-hosted runner attached is private.

## Testing Requirements

- [ ] A dev run executed with a runner online and another with all runners offline, both verified by run metadata.
- [ ] A warm-cache run verified by log timing.
- [ ] Negative test: a public repo cannot be generated from the template.

## Technical Notes

GitHub has no automatic fallback between runner groups; the ADR decides the mechanism (a probe job that checks runner status and selects, or two jobs with conditions). Runner labels can pin a run to one machine when a local cache matters.
