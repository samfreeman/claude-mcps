# PBI 001.010: Asks — a run stops, Sam answers, the run resumes

**Priority:** P2
**Dependencies:** PBI 001.005

## Description

A run that needs a human decision must not guess and must not hang. This slice delivers the ask: the run posts its question as a PR comment, checkpoints, and stops; orient reports the pending ask and its options; CV collects Sam's answer; save posts the answer as a reply and re-dispatches the run, which resumes from the checkpoint. This is the wagh hard-stop contract with GitHub comments in place of Telegram. It resolves Architecture open question 4 in its ADR.

Traces to PRD Epic 001 "a run that needs a human posts a comment and stops", Architecture decision 10.

## Deliverables

- A run that hits a hard-stop (snag, template drift, low-confidence high-blast-radius decision) writes a checkpoint on the feature branch, posts a comment on the PR or a linked issue stating the question and the options, and exits without failing the workflow.
- Orient on a project with a pending ask reports it first: the question, the options, and the run it belongs to.
- Save with an answer posts the reply on the same comment thread and re-dispatches the run with the checkpoint reference.
- The resumed run reads the checkpoint and the answer and continues; it does not redo completed work.
- A snag raised by a run is a hard-stop that also creates the snag file, so the next orient routes to tri rather than resume.

## Acceptance Criteria

- [ ] A run that reaches a low-confidence high-blast-radius decision stops with a PR comment stating the question and options, and orient on the project reports the ask.
- [ ] Saving an answer results in a reply on the thread and a new workflow run that reads the checkpoint and continues to a PR without repeating prior tasks.
- [ ] A run that raises a snag results in a snag file and orient reporting tri, not resume.
- [ ] Orient never reports a run as failed when it stopped on an ask.
- [ ] Two asks in sequence on one PBI are each answered and resumed in order.

## Testing Requirements

- [ ] Unit tests for ask detection from PR comments and workflow status.
- [ ] An end-to-end run on this repo against an ADR seeded with a deliberate hard-stop, answered from CV.
- [ ] Negative test: an answer saved with no pending ask refuses.

## Technical Notes

The hwag MCP already implements checkpoint and ask with a channel argument; the ADR decides whether the run uses it with a GitHub-comment channel or whether the workflow wrapper posts the comment.
