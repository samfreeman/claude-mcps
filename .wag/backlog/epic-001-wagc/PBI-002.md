# PBI 001.002: Save to the well-known home

**Priority:** P1
**Dependencies:** PBI 001.001

## Description

The save continuation: CV hands over artifacts and a pickup note, and the server writes each one to its well-known home. Before a repo exists the home is the project's planet in Dropbox; after, it is `.wag/` in the project repo. This slice delivers both homes and the rule that chooses between them, so a voice session can stop at any point and the next orient picks up mid-phase. It is the first write path and the first use of the Dropbox module.

Traces to PRD user story "I say save that and the decisions so far land in the planet", Architecture decisions 8 and 9.

## Deliverables

- The entry point accepts the save continuation with a payload of one or more artifacts, each typed (PRD, Architecture, RESEARCH, epic, PBI, ADR draft, decision capture, discovery note) and a pickup note.
- The server chooses the home per artifact from the project's state: planet when no repo exists, `.wag/` in the project repo when one does. CV supplies no paths.
- Planet writes go through the Dropbox module: a decision capture appends to today's dated decision doc; a draft document overwrites the previous draft; folders are created as needed.
- Repo writes go through the GitHub module as one commit per save, however many artifacts the payload carries, with a commit message the server composes.
- The pickup note is stored where the next orient will find it, and orient reports it as the position when a saved phase is resumed.
- Every artifact in the payload is validated by type before anything is written; one invalid artifact refuses the whole save with the reason.

## Acceptance Criteria

- [ ] For a project with no repo, saving a decision capture from CV results in a new or appended dated decision doc in that project's Dropbox planet.
- [ ] For a project with no repo, saving a PRD draft twice results in one file holding the second draft.
- [ ] For a project with a repo, saving a PRD edit and a new PBI in one call results in exactly one new commit on the project's dev branch containing both files.
- [ ] After a save with a pickup note, orient on the same project reports the note as the current position.
- [ ] A payload containing an artifact that fails type validation writes nothing and returns the reason.
- [ ] Save never changes the stored phase.

## Testing Requirements

- [ ] Unit tests for home resolution: no repo, repo present, each artifact type.
- [ ] Unit tests for the append-versus-overwrite rule by artifact type.
- [ ] Integration tests against a test planet folder and a test repo: single-artifact and multi-artifact saves, verifying one commit per save.
- [ ] Negative tests: invalid artifact, missing project, Dropbox or GitHub failure surfaced as a refusal with no partial write.

## Technical Notes

Multi-file commits need the Git Data API (blob, tree, commit, ref update), not the Contents API, which is one file per commit. Dropbox tokens and the planet root path are server configuration, never in the payload.
