# PBI 001.006: Merge and close from CV

**Priority:** P1
**Dependencies:** PBI 001.005

## Description

The end of a PBI's life from CV. With a PR open, approve in the merge position checks the PR is mergeable with green checks, merges it by squash, deletes the branch, moves the ADR to completed, moves the PBI to its completed mirror, runs the epic drain check, resets state, commits the closure on dev, and orients to the next PBI. Until this slice, wagc can build but not finish. The review gate (a review must exist) is added by PBI 001.007; here the check is mergeable and green.

Traces to PRD Goal 5 and user story "I say merge and the PBI closes", Architecture decision 6.

## Deliverables

- Orient with an open PR on the feature branch reports the PR, its check status and mergeability, and offers merge as the next step when they pass.
- Approve in the merge position checks: PR open, mergeable, all checks successful or skipped, no open snags. A failure refuses with the specific check and the ritual routes CV to discuss the fix rather than force it. An explicit override in the payload is honoured and recorded.
- A passing approve merges by squash, deletes the feature branch, moves the ADR to completed, moves the PBI to the epic's completed mirror, and commits those moves on dev in one commit.
- The epic drain check: when a feature epic's active folder holds only its epic file, the ritual asks whether to mark the epic done; on yes, the epic file is updated and moved and the active epic resets. Special buckets never drain.
- State is reset: active PBI and feature branch to null, phase to the next pick, active epic to general only when an epic closed.
- Orient after closure offers the next eligible PBI.

## Acceptance Criteria

- [ ] From CV, with a green mergeable PR, approving merge results in the PR merged by squash, the branch gone, the ADR under completed, the PBI under the completed mirror, and one closure commit on dev.
- [ ] With a failing check, approving merge refuses and names the check; nothing moves.
- [ ] With an explicit override in the payload, the merge proceeds and the override is recorded in the closure commit message.
- [ ] Closing the last PBI in a feature epic prompts for epic completion; yes moves the epic file and resets the active epic.
- [ ] Closing a PBI in the general bucket never prompts for drain.
- [ ] A PR already merged in the GitHub UI is detected, and approve completes only the closure steps.

## Testing Requirements

- [ ] Unit tests for the merge checks including override.
- [ ] Unit tests for closure file moves, epic drain detection, and state reset.
- [ ] Integration test on a test repo: open PR, merge, verify every move and the commit.
- [ ] Negative tests: conflicting PR, missing ADR, already-merged PR.

## Technical Notes

Squash merge and branch deletion are one PR API call. The closure moves are one Git Data API commit on dev after the merge lands.
