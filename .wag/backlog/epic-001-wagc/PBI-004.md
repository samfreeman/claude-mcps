# PBI 001.004: ADR by voice to a feature branch

**Priority:** P1
**Dependencies:** PBI 001.003

## Description

The adr phase from CV: orient lists the eligible PBIs across epics with a suggested default, the grill happens in conversation, drafts accumulate through save, and approve writes the approved ADR, creates the feature branch from dev, updates state, and advances to dev, all in one commit. The ADR's code examples and interfaces are written artifacts; the ritual tells CV how to summarise them for speech without dropping them from the document.

Traces to PRD Goal 3 and user story "I approve and the ADR is committed on its feature branch", Architecture decisions 6 and 7.

## Deliverables

- Orient in the adr phase returns: pre-flight (open snags, template drift, an active ADR to resume or replace), every open unblocked PBI grouped by epic with the suggested default, blocked work as a footnote, and the grill ritual.
- Picking a PBI (through save with the choice) records the active epic and PBI in state.
- Approve in the adr phase checks: the ADR has every required section, its status is approved, the PBI it cites exists and is open, no open snags. A failed check refuses with the gap.
- A passing approve, in one operation: writes the ADR under the active folder, creates the feature branch from dev, writes the feature branch and phase into state, and pushes the branch.
- The ritual covers voice: which parts of the ADR to read aloud, which to summarise, and the confirmation to obtain before approve.

## Acceptance Criteria

- [ ] From CV, orienting on a project in the docs-complete position lists eligible PBIs with priorities and a default, and blocked PBIs as a one-line footnote.
- [ ] Choosing a PBI and approving an ADR results in the ADR file on a new feature branch named for the PBI, state carrying that branch and the dev phase, in a single commit on that branch.
- [ ] Approving an ADR missing a required section refuses and names it.
- [ ] Approving when the feature branch already exists refuses rather than overwriting.
- [ ] A PBI whose dependencies are not all closed is not offered as selectable.
- [ ] Future-bucket PBIs touching the chosen PBI's area are surfaced as design context in the ritual.

## Testing Requirements

- [ ] Unit tests for eligibility across dependency states, including the future bucket.
- [ ] Unit tests for ADR section checks.
- [ ] Integration test on a test repo: pick, draft, approve, verify branch, file and state.
- [ ] Negative tests: existing branch, closed PBI, open snag.

## Technical Notes

Branch creation and the first commit on it are Git Data API operations from the dev branch's head. The ADR template in claude-home is the section authority.
