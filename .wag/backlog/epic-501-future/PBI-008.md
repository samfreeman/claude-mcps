# PBI 501.008: Vercel as a standard part of a Next.js project

**Priority:** P3
**Dependencies:** PBI 002.003

## Description

From the iPad there is no dev server. The way to see an app before it reaches production is a Vercel preview deployment: once a project repo is linked to a Vercel project, every push to a branch builds a preview with its own URL, and the URL lands on the PR. wagc's dev run ends at a PR (PBI 001.005), so the preview builds itself while the PR is open, and only the merge changes production. This slice makes Vercel a standard part of every Next.js project wagc creates: init links the new repo to a Vercel project, orient reports the preview URL when a PR has one, and the ritual tells CV how to offer it aloud. Vercel Hobby tier: preview deployments are included, and previews are protected by Vercel Authentication, which is a one-time sign-in on the iPad; password-protected previews are Pro-only and not needed for one user.

Traces to PRD Goal 4 (a dev run to an open PR without touching a laptop), Architecture decision 11 (modules under the wag surface), and the ADR 001.001 grill on 2026-09-04.

## Deliverables

- A Vercel module under the wag surface, holding a server-side Vercel token, able to create a project from a GitHub repo, read a deployment's status and URL, and nothing CV sees directly.
- Approve in the init position (PBI 001.008), for a project whose Architecture names Next.js, links the generated repo to a new Vercel project with dev as the preview branch and main as production; a project that does not name Next.js skips this without error.
- Adoption (PBI 001.012) offers the same link for an existing Next.js repo that has no Vercel project.
- Orient on a project with an open PR reports whether a preview deployment exists, its state (building, ready, failed) and its URL, and the ritual tells CV to offer the link rather than read it aloud unasked.
- The Vercel token is validated at startup per the validation policy and covered by the rotation procedure from PBI 002.003.

## Acceptance Criteria

- [ ] Init on a Next.js project from CV results in a Vercel project linked to the new repo, visible in the Vercel dashboard, with no manual import.
- [ ] After a dev run opens a PR on that project, orient reports a ready preview and its URL, and the URL opens the app on the iPad after the one-time Vercel sign-in.
- [ ] Orient on a PR whose preview failed to build reports the failure and points to the deployment.
- [ ] Init on a project that does not name Next.js creates no Vercel project and orient never mentions previews.
- [ ] Adoption on an existing Next.js repo with no Vercel project offers the link and, on yes, creates it.

## Testing Requirements

- [ ] Unit tests for the Vercel module against recorded responses, including a malformed response refused by its schema.
- [ ] Unit tests for the preview facts folded into orient's derivation, without changing any phase rule.
- [ ] Integration test: init a throwaway Next.js project, verify the linked Vercel project and a preview on its first PR, then delete both.

## Technical Notes

Vercel's REST API can create a project linked to a GitHub repo when the Vercel GitHub integration is installed on the account; that installation is a one-time manual step, not per project. The Hobby tier and the Vercel Authentication default for previews were the assumptions at authoring; re-verify both before the ADR relies on them. The preview URL and state are also readable from the PR's deployment statuses on GitHub, which orient already fetches, so the GitHub side may need no new call.
