# PBI 002.001: Durable audit log of every call

**Priority:** P2
**Dependencies:** PBI 001.002

## Description

Every call the server handles is recorded somewhere durable that the server controls, and the record is readable later from CV and from a desktop. Vercel function logs are short-lived; the good-faith period is exactly when the record matters. This slice decides the log's home (Architecture open question 3) and delivers the writer plus a way to read it back through the wag surface.

Traces to PRD Epic 002 and user story "I can read a log of every call CV made", Architecture decision 12.

## Deliverables

- Before the entry point returns, an entry is appended recording: timestamp, project, orient or the continuation, the artifacts touched and their homes, the outcome (acted, refused with reason, failed), and the caller identity.
- The log is append-only and survives redeploys; nothing in the server can rewrite or truncate it.
- The log's home is one the server owns or controls, chosen in the ADR.
- Orient offers a way to hear recent activity for a project, summarised for voice, and the full log is readable as a file from a desktop.
- A failed append does not silently pass: the call still completes, and the failure is reported in the response.

## Acceptance Criteria

- [ ] After a sequence of orient, save and approve from CV, the log holds one entry per call in order, each with the fields above.
- [ ] A refused approve is logged with the refusal reason.
- [ ] Redeploying the server leaves prior entries intact.
- [ ] Asking for recent activity on a project from CV returns a spoken summary of the last calls.
- [ ] An append failure is visible in the response that suffered it.

## Testing Requirements

- [ ] Unit tests for entry construction across outcomes.
- [ ] Integration test: calls against the live endpoint, then the log read back and matched.
- [ ] Negative test: log store unreachable, call completes, failure reported.
