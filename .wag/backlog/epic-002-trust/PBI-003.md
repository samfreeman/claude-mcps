# PBI 002.003: Harden the endpoint and its secrets

**Priority:** P2
**Dependencies:** PBI 002.002

## Description

The endpoint is public and gated by one header. The server holds a GitHub token, a Dropbox token and the mapping of projects; every run holds a subscription token. This slice hardens all of it: constant-time secret comparison, request size and rate limits, least-privilege token scopes, a documented rotation procedure for each secret with no downtime, and confirmation that no raw module tool is advertised to CV. Tier-bound features are re-verified on Vercel Hobby and GitHub Free.

Traces to PRD Epic 002 and constraint "the server's endpoint is public and gated by a shared secret header".

## Deliverables

- Shared-secret comparison that does not leak timing, and rejection before any tool or module runs.
- Request limits: body size cap and a per-caller rate limit appropriate to a single-user voice client, returning a clear refusal when exceeded.
- GitHub and Dropbox tokens scoped to the minimum the modules need, documented per scope, and verified by a test that a broader operation fails.
- A written rotation procedure for the shared secret, both API tokens and the subscription token in Actions, executed once end to end without a failed call.
- A check, run in tests, that the MCP tool list exposed to CV contains only the wag entry point.
- Every environment variable validated at startup per the validation policy; a missing or malformed one fails the deploy's first request loudly.

## Acceptance Criteria

- [ ] A request with a wrong secret is rejected in constant time and before any log of a tool call.
- [ ] A request over the body cap or the rate limit is refused with a clear message and logged.
- [ ] Attempting an operation outside each token's scope fails, proving the scope.
- [ ] Rotating each secret per the procedure results in no failed call from CV during the rotation.
- [ ] The tool list returned to CV contains exactly one tool.
- [ ] Removing a required environment variable produces a loud, named failure on the first request.

## Testing Requirements

- [ ] Unit tests for secret comparison, limits and environment validation.
- [ ] Integration tests for scope proofs against GitHub and Dropbox.
- [ ] A recorded rotation drill.
